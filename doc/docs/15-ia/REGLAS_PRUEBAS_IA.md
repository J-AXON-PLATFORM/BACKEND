# Reglas de pruebas para IA

> **Clasificación:** OBLIGATORIO

## Reglas

- no borrar, saltar o debilitar pruebas para obtener verde;
- clasificar fallo antes de corregir;
- preservar intención del requisito;
- aplicar TDD donde corresponda;
- elegir la capa mínima que demuestre el riesgo;
- usar pruebas de contrato en fronteras relevantes;
- usar sistema/E2E para integración y journeys críticos;
- activar resiliencia/rendimiento/migraciones/accesibilidad cuando el riesgo lo exija;
- separar defecto de producto, test, datos, entorno y causa desconocida;
- informar pruebas no ejecutadas;
- no convertir cobertura porcentual en objetivo de calidad por sí mismo;
- no depender exclusivamente de terceros reales en la suite frecuente.
