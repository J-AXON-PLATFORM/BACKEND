# Pruebas unitarias

> **Clasificación:** CONDICIONAL como capa; TDD está gobernado por `POLITICA_TDD.md`.

## Propósito

Dar feedback rápido sobre reglas y unidades aislables.

## Buenas pruebas

- rápidas;
- deterministas;
- legibles;
- centradas en comportamiento;
- sin depender de red/DB real.

## Evitar

- verificar detalles internos sin valor;
- mocks de cada línea;
- tests acoplados a implementación;
- perseguir cobertura porcentual sin analizar riesgo.

## Cobertura

La cobertura puede detectar huecos, pero no demuestra calidad.

Priorizar reglas críticas, bordes, errores y decisiones.
